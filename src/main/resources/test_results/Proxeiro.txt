The GET request procedure
----------------------------
When the client request for a new resource, the WebApp returns to the client the whole resource object entity
(eg. Pet entity), with all its containing object entities.
If the client needs from the resource particular info, we use the getters to filter what client needs from this entity.
For example:
public String getStatus() {return status.getName();}

The POST request procedure
------------------------------
Every entity we construct, we construct it according to what the client needs to GET or to POST.
This means that the entity we construct is what we need to produce to, or to consume from the client.
So, when the client wants to store to the database a new instance of this entity, the client needs to send
the whole entity as it is, with all its containing object entities.
In this case the setters have to set the whole containing object entities.
For example:
It is a mistake to set only the name of the entity "Status", because what we send to the server, is an entity which needs an
id, so it can be saved to the database normally.
The following snippet is a mistake:
public void setStatus(Status status) {this.status.setName(status.getName());}

Constructors and Setters
---------------------------
When the client sends a new resource to be saved to the server, the entity's attributes have to be filled with the data
the client sends to the server.
This is done by the setters in the entities. So the constructors are not needed at all.

Errors during the conversion of the entity to needed representation
----------------------------------------------------------------------
If we do mistakes like the followings:
1. The client does not send the whole entity as it is, with all its containing object entities.
2. The setters or the constructor do not set the whole containing object entities.
3. If for an attribute, we use 2 setters which have the same name but different parameters, the converter will
be confused which of them can use to set the attribute.
eg. void setAttr(int i){...}, and void setAttr(Integer i){...}

The conversion between the resource representation (eg. JSON) and the entities will fail, and the request
handler of the controller, will never be called. This is because the controller does not deal with the
representation of the resource, but is dealing with entities.

PersistentObjectException: Detached entity passed to persist
---------------------------------------------------------------
It does not commit, not rollback.
[Error]
result: Method threw 'javax.persistence.PersistenceException' exception.
detailMessage: org.hibernate.PersistentObjectException: detached entity passed to persist:
    com.thomasmylonas.petstore_api_web_app.data_access.entities.Pet
cause: org.hibernate.PersistentObjectException: detached entity passed to persist:
    com.thomasmylonas.petstore_api_web_app.data_access.entities.Pet
[Solution:]
We must have the followings:
1. Use the method: EntityManager.persist(...);
2. Declare GenerationType strategy using "Oracle custom sequence".
3. In the JSON for POST request, for every entity we need to persist, we have to declare their IDs as "null".
We don't need for these entities to declare specific IDs, because the GenerationType strategy will create
automatically them.
[Do not do:]
DO NOT the 2 followings together:
a. Declare GenerationType strategy.
b. In the JSON for POST request, for every entity we need to persist, we declare their IDs manually.

Hibernate: select hibernate_sequence.nextval from dual
----------------------------------------------------------
[Error]
Hibernate: select hibernate_sequence.nextval from dual while GenerationType.AUTO
[Do not do:]
DO NOT use: "@GeneratedValue(strategy = GenerationType.AUTO)", because for oracle, it creates automatically a sequence
(probably named hibernate_sequence).
This sequence is initially empty, and when it needs the next value, it cannot find it.

Significant notes
=====================

Notes on "GeneratedValue/GenerationType"
-------------------------------------------
[@GeneratedValue(strategy = GenerationType.AUTO)]
For oracle, it creates automatically a sequence (probably named hibernate_sequence).
[@GeneratedValue(strategy = GenerationType.IDENTITY)]
This type of generation relies on the IdentityGenerator which expects values generated by an identity column
in the database, meaning they are auto-incremented.

Note on "cascade/CascadeType"
--------------------------------
We should never cascade from "Child entity" to "Parent entity". Always cascade from "Parent entities" to "Children entities".
Because, a child entity cannot be created prior to its parent.
